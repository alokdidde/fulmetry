# S2 Viewport

**Status:** wave 2 (M1 realism, branch `s2/realism`) done on Linux. The rover renders from glTF meshes with materials,
soft shadows, ambient occlusion, MSAA and outlines on a pure white stage; picking is a ray cast on the real triangles;
a golden image guards the look. Wave 1 (`s2/wicked-spike`) is merged. Not yet tried on Windows or macOS.

## Current task (wave 2, M1): a realistic high-key render

Load each part's `meshFile` (binary glTF, part frame) and make the stage look like the UI spec's high-key reference
(`prototypes/workbench-highkey.png`): white world, white printed parts with grey shading and AO, bold colour blocks,
crisp dark outlines, a soft contact shadow on a white ground, anti-aliased edges, a 3/4 default view. Selection,
hover, x-ray and explode on the real meshes; mesh picking.

**Check:** `viewport_mesh` (every build), `viewport_wicked` (conformance with boxes and with meshes, mesh picking,
rotation, high-key pixels) and `golden_rover-wicked-highkey` (Wicked builds), plus the renders below, looked at.

Wave 1 task (done): build Wicked from a pinned commit, render the rover boxes headless, start `WickedViewport`.

## Blockers

   mesa-vulkan-drivers` (lavapipe), a Wicked checkout at the pinned sha with our patch applied, about 10 minutes
   to build the engine (4 cores), 1 GB disk and about 1.5 GB RAM per test process. Proposed job:
   `cmake -B build/wicked -G Ninja -DCMAKE_BUILD_TYPE=Release -DFULMETRY_WITH_WICKED=ON -DWICKED_ROOT=...`, then
   `ctest -R viewport_wicked`. Cache the shader cache dir (`FULMETRY_WICKED_SHADER_CACHE`) between runs; cold, the
   first render compiles shaders for about 60 s.
2. ~~`enable_testing()` comes after the module subdirectories~~: fixed at the root by S10; `app/viewport` no longer
   calls it.
3. **Not mine, seen while testing:** with `CMAKE_BUILD_TYPE=Release` (-O3) and warnings as errors, GCC 13 reports
   `-Wmaybe-uninitialized` in `app/core/include/fulmetry/core/Events.h:16` (std::variant of events) from
   `app/shell/src/main.cpp` and `app/tests/unit/test_fakes_conformance.cpp`. The `ci` preset (RelWithDebInfo) is
   unaffected. Owner: integrator / contracts.
4. **The vcpkg `full` preset cannot provide Wicked.** There is no vcpkg port; WickedEngine also has no install or
   export rules, so `find_package` is out. We build it from source with `add_subdirectory` (see below).
5. **CI for the Wicked path (S10), now with a golden.** In the job proposed in 1, run `ctest -R "viewport|golden_rover-wicked"`
   (about 20 s warm on 4 vCPU). The golden is lavapipe-specific (`app/viewport/tests/golden/rover-wicked-highkey.png`,
   Mesa 25.2 / LLVM 20 here): pin the Mesa version in the image, or let the job regenerate it once per Mesa bump with
   `FULMETRY_UPDATE_GOLDENS=1` and review the diff. On failure upload `build/.../golden-diffs/`.
6. **Contracts (integrator): `ViewportConformance` assumes the centre of `Part.bounds` is on the part.** "Every part can
   be picked when isolated" picks the projected bounds centre. That holds for boxes, not for meshes with a hole in the
   middle: with the stand-in meshes the fasteners part (eight screws around a rectangle) fails it, correctly. Suggest
   the suite pick a point the implementation reports as on the part (for example a new `IViewport::anchorPoint(part)`,
   or `project()` of the first `pick()` hit found by scanning the part's projected bounds). Until then the mesh run of
   the suite leaves the fasteners mesh out (`test_wicked_viewport.cpp`).
7. **Real rover meshes.** Another stream is building them under `fixtures/rover/meshes/`. When they land, the fixture's
   `meshFile` entries make them load with no S2 change (paths are relative to the project file's directory, which
   `WickedOptions::assetRoot` names). The golden then wants regenerating against them.

## Decisions and findings

### Pinned Wicked Engine

- Repo: https://github.com/turanszkij/WickedEngine (MIT)
- Commit: `bee31c0309c03fbf8e793af9fdda253b213685be` (2026-11-07, "impostor buffer grow flickering fix")
- Local patch: `app/viewport/wicked/patches/0001-lazy-object-psos.patch` (15 lines, `wiRenderer.cpp`). See "Memory".

### Build steps (Linux)

```sh
sudo apt-get install -y libsdl2-dev libvulkan-dev mesa-vulkan-drivers   # lavapipe = software Vulkan 1.4
git clone https://github.com/turanszkij/WickedEngine.git ~/deps/WickedEngine
git -C ~/deps/WickedEngine checkout bee31c0309c03fbf8e793af9fdda253b213685be   # a --depth 1 clone needs `git fetch --depth 1 origin <sha>` first
git -C ~/deps/WickedEngine apply $PWD/app/viewport/wicked/patches/0001-lazy-object-psos.patch
cmake -B build/wicked -G Ninja -DCMAKE_BUILD_TYPE=Release -DFULMETRY_WITH_WICKED=ON -DWICKED_ROOT=$HOME/deps/WickedEngine
cmake --build build/wicked -j4                       # about 10 min, mostly the engine
ctest --test-dir build/wicked -R viewport            # conformance + spike PNG
./build/wicked/app/viewport/fulmetry_wicked_spike fixtures/rover/fulmetry.project.json rover.png 640 400 [explode]
```

How it is wired (all in `app/viewport/`):
- `CMakeLists.txt`: default OFF keeps the old INTERFACE target, so fakes-only builds are untouched. ON requires
  `WICKED_ROOT` (cache PATH, the checkout root) and builds `fulmetry_viewport` (static), the spike and the test.
- `wicked/CMakeLists.txt`: `add_subdirectory(${WICKED_ROOT} ... EXCLUDE_FROM_ALL SYSTEM)` with Wicked's editor,
  samples and tests off. It clears our `-Wall -Wextra -Wpedantic` and warnings-as-errors for the engine tree only;
  our own code still builds with them (checked with `-DCMAKE_COMPILE_WARNING_AS_ERROR=ON`).
- Runtime: Wicked compiles HLSL at runtime with `libdxcompiler.so` (shipped in the Wicked repo), loaded from the
  executable's directory; a post-build step copies it there. Compiled shaders are cached in
  `$FULMETRY_WICKED_SHADER_CACHE` (default `/tmp/fulmetry-wicked-shaders/`, 22 MB).
  `FULMETRY_WICKED_THREADS` caps Wicked's job threads.

### Meshes (wave 2)

- **Loader:** cgltf 1.14 (MIT), vendored as one header in `app/viewport/third_party/cgltf/`. Wicked's own glTF importer
  lives in its Editor (`Editor/ModelImporter_GLTF.cpp`, tinygltf), not in the engine library, so it is not usable.
- `fulmetry_viewport_mesh` (`MeshAsset.h/.cpp`) has no GPU or Wicked dependency and builds in **every** configuration,
  so loading and picking are tested in the default CI build (`viewport_mesh`).
- **Frame and units:** a `.glb` holds the part in its own frame (the frame of `Part.bounds`). glTF says metres and +Y up,
  which is what build123d writes (S8). Files written in millimetres or Z up also exist, so the loader tries the four
  readings (m/mm x Y-up/Z-up) and keeps the one whose extent best matches `Part.bounds` (log-size distance; glTF's own
  reading wins ties). `MeshAsset::units` says which one was used. Node transforms are applied; a mirroring node flips
  winding back; missing normals are computed.
- **Materials:** each glTF primitive becomes a Wicked subset with its own material: base colour, roughness, metallic.
  A primitive whose base colour is glTF's default white (no material, or factor 1,1,1,1 without a texture) takes
  `Part.color`, so a plain export is drawn in the part's palette colour. Textures are not read yet.
- **Fallback:** no `meshFile`, or a file that fails to load, draws a box over `Part.bounds` and adds a line to
  `WickedViewport::meshWarnings()`. Boxes go through the same mesh path (and picking) as files.
- **Stand-in meshes:** `app/viewport/spike/testmeshes/make_testmeshes.py` (numpy only) writes one `.glb` per rover part:
  filleted boxes with analytic normals (chassis tub with an open top, top shell with deck and grille, battery, boards
  with chips and headers) and lathed profiles (wheels with a lugged chevron tread, rim and spokes; motors, lens,
  ball caster). 1.2 MB in total, written like build123d (metres, Y up) so the conversion is exercised.
- **Handedness:** Fulmetry triangles wind counter-clockwise from outside. After the y/z swap into Wicked's
  left-handed frame the same index order is what Wicked treats as front-facing (`front_counter_clockwise`), so indices
  are copied as they are. Part rotations map as `q' = (w, -x, -z, -y)`.

### Picking

`pick()` casts the ray against each visible part's triangles (part frame, Moller-Trumbore, bounds slab test first) and
returns the nearest hit with its world point and outward normal. It does **not** use Wicked's `Scene::Intersects`:
that needs `Scene::Update`, which needs the GPU device, and `pick()` must work before the first frame and in a
viewport that never renders (conformance, the agent bridge). The triangles are exactly the ones Wicked draws, so the two
agree. Rough cost: 60k triangles in the rover, about 1 ms per pick on one core; a BVH can come later.

### Look (high-key stage)

All in `WickedViewport.cpp`, constants at the top, tuned by eye on lavapipe renders at 1280x800:
- **Ground:** a white plane under the lowest visible part, 800 units wide. From any view above the horizon it fills the
  frame, so no background trick is needed and outlines are never clipped. The wave 1 stencil compose (white where no
  geometry) is kept for low views that see the sky, when MSAA is off.
- **Light:** one directional key light high behind-left of the default view (shadow falls to the front-right), one
  fill from the camera side without shadow, a dim sky for ambient. Uchimura tonemap (linear mid-tones, soft shoulder)
  plus a 0.012 brightness lift: the unshadowed ground reaches exactly 255, tops of white parts about 250, side faces
  205-215, shadows about 200-230.
- **Soft shadow:** `renderToImage` averages `WickedOptions::frames` frames (default 8) with the key light moved over a
  0.08 rad disk (golden-angle spiral), into an fp16 accumulator: an area light. One frame gives a hard but clean shadow.
  Two cascades: a 4096 px one sized to the camera distance x 1.6 (holds the stage), and a coarse one to the far plane.
  Screen-space contact shadows are on.
- **AO:** Wicked SSAO, range 30 mm, power 1.6. MSAO grey-ringed the model with a halo and greyed the far ground;
  HBAO is computed at reduced resolution and left blocky steps along every shadow edge. RTAO needs ray tracing, which
  lavapipe does not offer.
- **Anti-aliasing:** MSAA 4x (`WickedOptions::msaa`; 1 switches to FXAA). TAA is off (it needs many frames to settle).
- **Outlines:** Wicked's depth outline, about 1 px at 800 px height, dark grey. Against the ground they are complete
  (the wave 1 half-clipping is gone).
- **Selection:** red outline (2.6 px at 800 px height) over a white halo, so it reads on red parts too. Hover: a thinner
  half-transparent red outline. Both come from user-stencil masks of the part and `Postprocess_Outline`, so only the
  visible part of a selected part is outlined.
- **X-ray:** every part except the selected one at 40% opacity; the selected part stays solid.
- **Explode:** reworked like an assembly drawing: offsets from the object centre scaled (1.2, 1.4, 2.5) in x, y, z, never
  downwards, so lids and heads lift most and internals stay in the opened body. Still reversible; differs from the
  fake's radial rule (only `drawnPlacement` is shared, and that reports what is drawn).
- **Default view:** `resetView()` frames what is visible in a 3/4 view from front-left and above (30 deg FOV): every
  visible part's bounds corners are centred and fill 70% of the frame. `loadProject` calls it; call it again after
  `showObject` or explode.

### Frame time (lavapipe, 4 vCPU shared with other jobs, no GPU)

| `renderToImage` | 640x400 | 1280x800 |
| --- | --- | --- |
| First call, warm shader cache (device, init, scene, first frames) | 5.0 s | 5.7 s |
| Steady, `frames = 1` (one frame + compose + readback) | 260 ms | 920 ms |
| Steady, `frames = 8` (default, soft shadow) | 2.0 s | 5.8 s |
| First call, cold shader cache | | 63 s |

So one frame of the full look costs about 0.25 s at 640x400 and 0.8 s at 1280x800 on lavapipe (wave 1 boxes: 40 ms
and 70 ms at 640x400 and 960x600): MSAA 4x, two 4096 px shadow cascades, SSAO and 60k triangles, all on the CPU.
On a GPU these are a few ms. Peak RSS of the spike at 1280x800: 1.48 GB warm (wave 1: 0.94 GB at 640x400), mostly the
shadow atlas and the multisampled targets. For a live view the averaging should be progressive: show frame 1 at
once and refine while the camera is still.

### Memory: eager pipeline compile, and the patch

Unpatched, Wicked's `LoadShaders()` creates every object pipeline permutation (render pass x material type x mesh
shader x blend x cull x tessellation x alpha test x MSAA, thousands) on background jobs. Each one is a full LLVM
compile on lavapipe. RSS grew about 170 MB/s and the process was OOM-killed at about 14 GB. `FULMETRY_WICKED_THREADS=2`
did not help. The patch passes `nullptr` render pass info for object PSOs when `WICKED_LAZY_OBJECT_PSO` is defined
(our `wicked/CMakeLists.txt` defines it when the patch is present). Wicked's Vulkan backend then compiles each
pipeline on first use. Peak RSS of the spike is now 0.94 GB (wave 1 boxes; 1.48 GB with the wave 2 look at 1280x800). On a real GPU eager compile is the better choice (no first-use
hitch). Suggest an upstream option, or define it only for software Vulkan.

### Other findings

- Object pipelines are published at `EVENT_THREAD_SAFE_POINT`, so a one-shot render must wait for
  `wi::renderer::IsPipelineCreationActive() == 0` and fire that event, or it draws only the sky. Without the wait
  the process also crashes at exit: static teardown destroys the device while jobs still use it.
- FAudio logs `FAudio_CreateMasteringVoice` error (no audio device in the container); harmless.
- Wicked keeps global renderer state: one device per process, created on first render (`Engine` singleton).
  Several `WickedViewport`s share it; each has its own `Scene`, `RenderPath3D` and camera.
- If no Vulkan 1.3 device exists, Wicked shows a message box and calls `exit()`, so `renderToImage` cannot return an
  error. Needs a pre-flight device check before we hand it a user's machine.
- Coordinates: Fulmetry is right-handed, Z up, mm. Wicked is left-handed, Y up. Swapping y and z converts between
  them (the swap is a mirror, which is the handedness change); scale 0.01 units/mm.

### Gaps against ViewportConformance and IViewport

`ctest -R viewport`: conformance passes with boxes and with the stand-in meshes (fasteners left out, blocker 6), plus
mesh picking, rotation and high-key checks; 240 assertions. Still thin:
- **Faces:** `PickHit::face` stays empty (needs S3's face ids on the mesh).
- **X-ray** draws no outline around the solid selected part, probably because Wicked's transparent pass overwrites the
  user stencil the mask reads (not checked). Ghosted white parts are faint on the white stage.
- **Joints, slice plane and `StageStyle::Realistic`** are stored but not drawn.
- `update(dt)` does nothing yet; frames are only driven by `renderToImage`. There is no on-screen path.
- glTF textures, vertex colours and KHR material extensions are ignored; non-uniform node scales get approximate normals.
- Shadow and AO quality depend on scale: the cascade follows the camera distance, AO range is fixed at 30 mm.
- Wicked writes `log.txt` into the working directory (its backlog); harmless, but tests run from the build tree.

### Raven GUI sharing: shared Vulkan device vs native child window

Options for putting the stage inside the Raven GUI window:
1. **Native child window.** Wicked owns a child HWND / X11 / Wayland subsurface / NSView inside the Raven window,
   with its own swapchain. This is what `GraphicsDevice_Vulkan(window)` and `CreateSwapChain` already expect, so it
   is the least code. Costs: Raven GUI cannot draw over the 3D view (comment pins, labels, hover cards) without a
   second overlay window, plus resize and focus juggling on each platform. Wayland subsurfaces and macOS layers
   make it worse.
2. **Shared device, texture handoff.** Wicked renders offscreen (what the spike does) and Raven GUI draws that
   texture as a widget, so overlays come for free. If Raven GUI is Vulkan, the cleanest form is one `VkDevice`.
   Wicked creates its own instance and device and has no "adopt an external device" constructor, so we would
   patch `GraphicsDevice_Vulkan` or let Raven render on Wicked's device. With two devices, share the image through
   `VK_KHR_external_memory_fd` / win32 handles plus an external semaphore. Wicked already enables external memory
   (it has an external-memory VMA pool).
3. **Copy through the CPU** (what `renderToImage` does now): fine for agent renders and tests, too slow for a live
   view (readback costs several ms even on a GPU).

**Recommendation:** use option 2 (offscreen render, Raven GUI composites it). We need to find out from the Raven GUI
side (S5): which graphics API it uses on each OS (Vulkan everywhere, or Metal/D3D?), and whether it can take an
external `VkImage` or import a shared handle. If Raven GUI is not Vulkan on macOS/Windows, use external-memory
interop or, on macOS, Wicked's Metal backend. Fall back to option 1 only if neither works.
