# S8 Engine worker

**Status:** wave 1 done on `s8/cad-build` (cad.build implemented, tests green with and without build123d)

## Current task (wave 1)

Implement cad.build with build123d: a parametric wheel source in fixtures/rover/cad/, built to STEP and glTF with a source hash.

**Check:** pytest builds the wheel; result matches the cad.build contract; bounds match the manifest's wheel within 0.5 mm.

## Installing engines

The base worker needs only Python 3.12+ and jsonschema. Engines are opt-in extras:

```sh
pip install -e 'worker[test]'          # base: CAD tests skip
pip install -e 'worker[test,cad]'      # + build123d (pulls cadquery-ocp wheels, ~150 MB)
cd worker && pytest -q
```

or with pixi: `pixi run -e cad test` inside `worker/` (pixi path not yet exercised). build123d 0.13 installs from PyPI wheels on Python 3.12
and 3.13 (checked on Linux x86-64, Python 3.13). `worker.ping` reports installed engines, e.g.
`{"engines": {"build123d": "0.13.0"}}`.

## CAD source convention

- Part `part:<object>/<slug>` has its source at `<projectRoot>/cad/<object>/<slug>.py`.
  Example: `part:rover/wheel-l` -> `fixtures/rover/cad/rover/wheel-l.py`.
- The file defines `PARAMS: dict` (JSON-serialisable defaults) and `build(params: dict) -> build123d Part`.
  `build` receives `PARAMS` updated by any overrides and returns a valid solid.
- Geometry is in mm, in the part's own frame: the frame the manifest's `bounds` are given in (placement is applied
  by the app, not by the source).
- `sourceHash` = `"sha256:" + sha256(source file bytes + JSON(params, sorted keys, compact))`.
- Outputs: `<projectRoot>/.fulmetry/build/<object>/<slug>.step`, `.glb`, and `.json` (hash, params, bounds).
  Same hash and both files present -> cached result, nothing rebuilt. The .json is written last and removed before
  a rebuild, so a crash never leaves a hash pointing at half-written files.
- Result paths are absolute.
- The GLB follows glTF conventions: **metres, +Y up** (build123d's exporter rotates Z-up to Y-up and scales mm to
  m). STEP stays in mm, Z-up. Mesh tolerances: 0.05 mm linear, 0.2 rad angular (~130 KB for the wheel).

## Errors

All failures come back as JSON-RPC errors; the worker keeps serving.

| Code | Meaning |
| --- | --- |
| -32602 | params do not match the contract, or the part id is not `part:<object>/<slug>` (lowercase, no `/..`) |
| -32010 | no source file where the convention says (`data.expected` has the path) |
| -32011 | the source failed to load, `build()` raised, or it did not return a valid solid |
| -32012 | build123d is not installed in this worker |
| -32603 | anything else unexpected |

Codes live in `worker/fulmetry_worker/errors.py`.

## Blockers

**Proposed contract change (for a `contract/cad-build-params` branch):** the app cannot yet override a part's
params through RPC. The worker already supports it internally (`cad.build(root, part, overrides)`); exposing it needs
an optional `params` object in cad.build's params, plus an optional `cached` flag in the result so the app can show
"up to date" without comparing hashes:

```json
"params": {
  "type": "object",
  "required": ["projectRoot", "part"],
  "additionalProperties": false,
  "properties": {
    "projectRoot": {"type": "string"},
    "part": {"type": "string"},
    "params": {"type": "object", "description": "Overrides merged over the source's PARAMS; part of sourceHash"}
  }
},
"result": {
  "...": "as now, plus",
  "properties": {"cached": {"type": "boolean"}}
}
```

**For S10:** add `.fulmetry/` to the root `.gitignore` (build outputs under a project root), and a CI job that
installs the cad extra (see Checks added).

## Decisions and findings

- Outputs go to `.fulmetry/build/<object>/<slug>.*`, not `.fulmetry/build/<slug>.*`: slugs are unique only within an
  object, and the rover fixture already has `rover/battery` and `remote/battery`.
- The wheel (`fixtures/rover/cad/rover/wheel-l.py`): Ø60 x 14 mm TPU wheel, axle along Y, 24 axial tread grooves
  (2 x 1.5 mm) offset half a pitch so lands sit at the ±X/±Z extremes and the tight bounds are exactly 60 x 14 x 60;
  ring pockets on both faces leave a 6 mm web and a Ø12 mm hub; a Ø3 mm N20-style D-shaft bore (2.5 mm across the
  flat, +0.1 mm clearance). Solid volume 23.7 cm³.
- Bounds use `bounding_box(optimal=True)`, rounded to 0.1 µm; the wheel comes out at exactly ±30, ±7, ±30.
- A cold build of the wheel takes about 2.5 s, most of it importing OCP; a cached call takes milliseconds (the source
  is still executed to read `PARAMS`, which is cheap).
- `server.main()` now keeps the real stdout for replies and points fd 1 at stderr, so OCCT/KiCad C++ code that prints
  to stdout cannot corrupt the JSON-RPC stream.
- Sources are executed in-process with full Python: they are trusted project code, like a build script.

## Checks added

- `worker/tests/test_cad.py`
  - always: missing source -> -32010 with the expected path; malformed part ids -> -32602; hash covers source and
    params and ignores key order; without build123d, cad.build answers -32012.
  - with build123d (`pytest.importorskip`): the wheel builds; the result validates against
    `contracts/worker/cad.build.json`; STEP and GLB files are real (`ISO-10303-21`, `glTF` magic); bounds match the
    manifest's `part:rover/wheel-l` within 0.5 mm; a second call is a cache hit (same result, files untouched);
    a param override and an edit to `PARAMS` both change `sourceHash`; `build()` raising and a syntax error both
    come back as -32011 and the worker still answers `worker.ping`.
- CI: the existing `worker` job runs these with the CAD tests skipped. Proposed `worker-cad` job for S10
  (ubuntu-24.04, Python 3.12): `pip install -e 'worker[test,cad]'`, then `cd worker && pytest -q`.
