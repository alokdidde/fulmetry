## Decisions and findings

- `fulmetry::CheckGraph` (`app/project/include/fulmetry/project/CheckGraph.h`) edits a `Project&` in place:
  - `partChanged(part, hash)` sets every check that lists the part and has not recorded that hash to
    Unresolved with reason `Changed: <part name>`, writes the hash into `inputHashes`, and returns the
    changed check ids. Same hash again returns an empty list and touches nothing. Unknown part: `not_found`.
  - `recordVerdict(check, Supported|Refuted, reason)` stores the verdict and replaces `inputHashes` with the
    current hash of each input (inputs with no known hash are left out). `Unresolved` is `invalid_argument`.
  - `checksFor(part)` and `currentHash(part)` for callers (UI chips, agents).
- After `partChanged`, `inputHashes[part]` holds the hash that invalidated the check, not the hash it last
  ran against. That is what makes a repeated hash a no-op; the verdict (Unresolved) says the run is stale.
- The root calls `enable_testing()` after `add_subdirectory(app/project)`, so `app/project/CMakeLists.txt`
  calls it too; otherwise `project_tests` is never registered with ctest.
- GCC 13+ flags `const T& f(const Project&, const std::string&)` called with a literal as
  `-Wdangling-reference` under `-Werror`; the test helper returns a copy.

## Checks added

- ctest `project_tests` (`app/project/tests/`, doctest, fixture `fixtures/rover`):
  - editing wheel-l flips `chk:rover/rug`, and only it, to Unresolved with `Changed: Left wheel`;
  - the same hash twice is a no-op, a new hash invalidates again;
  - `recordVerdict` stores the current input hashes; error codes for unknown part/check and Unresolved;
  - `serializeProject`/`parseProject` keeps `inputHashes` byte-stable, and a graph built from the loaded
    project treats the saved hash as current.
