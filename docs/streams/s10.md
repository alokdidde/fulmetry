## Engine pins: `tools/deps.json`

The one place to change an engine version. CI reads it through `tools/fetch_dep.py`, and so can you:

```sh
python3 tools/fetch_dep.py fetch mujoco ~/deps/mujoco    # release tarball, sha256 checked
python3 tools/fetch_dep.py fetch wicked ~/deps/wicked    # git commit + app/viewport/wicked/patches/*.patch
python3 tools/fetch_dep.py fetch raven  ~/deps/raven     # git commit
python3 tools/fetch_dep.py key wicked                    # cache key: wicked-<sha>-<patch hash>
```

A fetch is idempotent: the destination carries a marker with its key, so a second fetch (or a directory restored
from a CI cache) is left alone, mtimes included. A changed pin or patch changes the key, and the next fetch moves the
checkout and re-applies the patches. **S2, S4, S5:** please point your stream docs at `tools/deps.json` for the pin
(today the same sha/version is written in s2.md, s4.md and s5.md); bump a pin with a PR that changes `tools/deps.json`
(S10 reviews), together with your module change if it needs one.

Each engine has a configure, build and test preset that takes the checkout from the environment:

```sh
MUJOCO_ROOT=~/deps/mujoco    cmake --preset ci-mujoco && cmake --build --preset ci-mujoco && ctest --preset ci-mujoco
WICKED_ROOT=~/deps/wicked    cmake --preset ci-wicked && cmake --build --preset ci-wicked && ctest --preset ci-wicked
RAVEN_GUI_ROOT=~/deps/raven  cmake --preset ci-raven  && cmake --build --preset ci-raven  && xvfb-run -a ctest --preset ci-raven
```

They inherit `ci` (warnings as errors, `noTestsAction: error`, 300 s per test) and run the whole suite, so the fakes'
tests also run against an engine-enabled build. `ci-wicked` is Release (as S2 measured it) and carries
`-Wno-error=maybe-uninitialized` until the Events.h fix below lands; remove that flag then.

**Why paths filters for Wicked and Raven only.** Wicked is the one expensive job: a cold engine build is about 6 min on
4 dedicated cores here (expect 15-20 on a 4-vCPU runner; a 2-vCPU private-repo runner would be slower) plus 50 s of shader compiles.
Raven needs Xvfb and a ~45 s GUI run. Both depend on a small set of paths, so a `changes` job (plain `git diff`
against the base, no third-party action) turns them on for PRs that touch:

- both: `app/core/`, `app/project/`, `app/shell/`, `app/tests/`, root `CMakeLists.txt`, `CMakePresets.json`,
  `tools/deps.json`, `tools/fetch_dep.py`, `tools/cmake/`, `.github/workflows/ci.yml`
- Wicked also: `app/viewport/`, `fixtures/rover/`; Raven also: `app/ui/`

Skipped jobs count as passed for branch protection, unlike workflow-level `paths:` filters, which leave a required
check pending. Pushes to main and `workflow_dispatch` run everything, and those runs are what save the caches: a PR
can restore caches saved on main, not ones saved on another PR's branch. Node and MuJoCo are cheap with caches,
so they always run. All four are Linux only; Windows and macOS keep building the fakes in `app`.

**Wicked caches** (keyed on `wicked-<pin>-<patch hash>`):
- Build: the patched checkout and `build/ci-wicked` in one cache. `actions/cache` restores mtimes, so Ninja keeps
  every engine object and rebuilds only the 32 steps the fresh repo checkout touched (checked here: `touch` every
  tracked file, rebuild, 0 engine objects recompiled). Saved right after the build step, so a red test does not lose
  it. `restore-keys: wicked-` lets a pin bump start from the previous build. Size: 1.1 GB checkout (345 MB of it
  `.git`, 487 MB `Content/`) plus 400 MB build dir, before compression.
- Shaders: `FULMETRY_WICKED_SHADER_CACHE` (22 MB); saved only when the tests passed. Cold suite 78 s, warm 14 s.
- The checkouts live in `<workspace>/../deps` (fixed absolute path: the cached build dir records it).

## Release with warnings as errors (pending: needs a contract fix)

Reproduced S2's report. `cmake -S . -B build/rel -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_COMPILE_WARNING_AS_ERROR=ON`
fails with GCC 13.3 (`-O3`); Clang 18 Release passes (7/7), and the `ci` preset (RelWithDebInfo, `-O2`) passes.

```
app/core/include/fulmetry/core/Events.h:16:8: error: '...ViewModeChanged::xray' may be used uninitialized [-Werror=maybe-uninitialized]
app/tests/fakes/FakeAgentClient.h:43:27: note: '<anonymous>' declared here
```

in `app/shell/src/main.cpp` and `app/tests/unit/test_fakes_conformance.cpp`. It is a GCC false positive: line 43
builds `Event{ChatPosted{...}}`, and GCC's -O3 inlining of the `std::variant` move constructor reports the bytes of
another alternative (`ViewModeChanged`, three bools and an optional, all initialised) as maybe uninitialised. No
value is read uninitialised. It is still a real Release build break, so it needs fixing in `app/core` (contract stream).

**Exact fix (contract stream), `app/core/include/fulmetry/core/Events.h` line 16:** wrap the struct in a GCC-only
diagnostic pragma. Checked here: GCC 13 Release with warnings as errors builds and 7/7 tests pass.

```cpp
// GCC 12-13 at -O3 report a false -Wmaybe-uninitialized for this struct when std::variant<..., ViewModeChanged, ...>
// is move-constructed from another alternative. Silence it for this struct only.
#if defined(__GNUC__) && !defined(__clang__)
#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wmaybe-uninitialized"
#endif
struct ViewModeChanged { bool exploded = false; bool joints = false; bool xray = false; std::optional<PartId> isolated; };
#if defined(__GNUC__) && !defined(__clang__)
#pragma GCC diagnostic pop
#endif
```

Alternative (also checked, also green): put `std::optional<PartId> isolated;` first in the struct. That changes the
aggregate's member order (nobody brace-initialises it today), and it only works because it moves the bools away from
where GCC's analysis looks, so it may break again with another GCC. Prefer the pragma.

**Pending job**, to add (S10) once the fix is on main, and to drop `CMAKE_CXX_FLAGS` from `ci-wicked` at the same time:

## How to use golden images

```cmake
fulmetry_add_golden_test(NAME my-view                     # golden: fixtures/golden/my-view.png
  COMMAND $<TARGET_FILE:fulmetry> --project ... --render my-view.ppm
  OUTPUT my-view.ppm
  THRESHOLD 8 MAX_RMSE 6.0 MAX_FRACTION 0.002)            # defaults: 8, 4.0, 0.002
```

- `tools/imgdiff` (`fulmetry_imgdiff compare|convert`) reads PPM (P6/P3) or PNG, reports RMSE (0..255 units over
  RGB samples) and the fraction of pixels whose largest per-channel delta exceeds THRESHOLD. Exit 0 pass, 1 over a
  limit or size mismatch, 2 usage or I/O error. PNG via vendored stb (`third_party/stb`, MIT/public domain).
- A failing test copies `actual.png`, `golden.png`, `diff.png` (red: over threshold, amber: under threshold, grey:
  equal) to `build/<preset>/golden-diffs/<name>/`; CI uploads that folder as `golden-diffs-<os>`.
- `EXPECT_MISMATCH` makes a test pass only on imgdiff exit 1, so a crash or a missing file never counts as the
  expected failure (stricter than `WILL_FAIL`).
- Intended visual change: `FULMETRY_UPDATE_GOLDENS=1 ctest --preset dev -L golden`, look at the PNG, commit it.
- The helper lives in `tools/cmake/FulmetryGolden.cmake` and is included by the root CMakeLists when tests are on,
  so any module's CMakeLists can call it.

## Decisions and findings

- Tolerances for `rover-fake-iso`: THRESHOLD 8, MAX_RMSE 6.0, MAX_FRACTION 0.002 (128 of 64000 pixels).
  The fake renderer only produces exact palette colours (shade is 0.6 or 1.0), so cross-compiler drift can only
  flip whole edge pixels. Measured locally: GCC 13 `-O2`, GCC `-O3 -ffp-contract=fast -march=haswell` (FMA),
  GCC `-O2 -ffast-math`, clang 18 `-O0` and clang `-O2 -ffp-contract=fast -march=haswell` all render bit-identical
  to the golden (RMSE 0). The limits still allow ~50 flipped high-contrast edge pixels for arm64/MSVC.
- Moving the camera head 10 mm (`golden_rover-fake-iso-head-moved`, generated from the fixture at configure time
  with `string(JSON)`) gives RMSE 14.1 and 0.76 % over threshold: 2.3x and 3.8x the limits.
- No build-dir cache in CI: the fakes-only build is ~12 Ninja steps (seconds), and a restored Ninja dir is rebuilt
  anyway because checkout resets source timestamps. Revisit with ccache once Wicked/OCCT build in CI.
- macOS runner is `macos-latest` (Apple silicon); `macos-14` jobs were cancelled before start.
- `enable_testing()` now runs before the module `add_subdirectory` calls, so module-level `add_test()` registers.
- `ci` test preset: `--output-on-failure`, `noTestsAction: error`, 300 s per-test timeout.
- `.gitignore` is now owned by S10 (`tools/streams.json`); `.fulmetry/` (per-project build outputs) is ignored.
