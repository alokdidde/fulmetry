## Current task (wave 1)

## How to use golden images

```cmake
fulmetry_add_golden_test(NAME my-view                     # golden: fixtures/golden/my-view.png
  COMMAND $<TARGET_FILE:fulmetry> --project ... --render my-view.ppm
  OUTPUT my-view.ppm
  THRESHOLD 8 MAX_RMSE 6.0 MAX_FRACTION 0.002)            # defaults: 8, 4.0, 0.002
```

- `tools/imgdiff` (`fulmetry_imgdiff compare|convert`) reads PPM (P6/P3) or PNG, reports RMSE (0..255 units over
  RGB samples) and the fraction of pixels whose largest per-channel delta exceeds THRESHOLD. Exit 0 pass, 1 over a
  limit or size mismatch, 2 usage or I/O error. PNG via vendored stb (`third_party/stb`, MIT/public domain).
- A failing test copies `actual.png`, `golden.png`, `diff.png` (red: over threshold, amber: under threshold, grey:
  equal) to `build/<preset>/golden-diffs/<name>/`; CI uploads that folder as `golden-diffs-<os>`.
- `EXPECT_MISMATCH` makes a test pass only on imgdiff exit 1, so a crash or a missing file never counts as the
  expected failure (stricter than `WILL_FAIL`).
- Intended visual change: `FULMETRY_UPDATE_GOLDENS=1 ctest --preset dev -L golden`, look at the PNG, commit it.
- The helper lives in `tools/cmake/FulmetryGolden.cmake` and is included by the root CMakeLists when tests are on,
  so any module's CMakeLists can call it.

## Blockers

None blocking. Suspected portability issues in code S10 cannot edit, for the owners (integrator / contract):

- MSVC /W4 is clean today (first CI run on main passed on windows-2022 with warnings as errors), so no MSVC item.
- `-Wconversion`-level warnings (not on in CI; listed in case a stricter warning set is adopted, and as the places
  a future MSVC `C4267`/`C4244` would show up first), seen with clang 18 `-Wconversion`:
  - `app/tests/fakes/FakeViewport.h:108` int to size_t sign change (`size_t(w) * h * 4`)
  - `app/tests/fakes/FakeViewport.h:114` int to size_t sign change (`(size_t(y) * w + x) * 4`, twice)
  - `app/tests/fakes/FakeViewport.h:146` size_t to double may lose precision (`s * (1.0 / o->parts.size())`)
  - `app/tests/fakes/FakeViewport.h:195` int to size_type sign change (`p->color.substr(i, 2)`)
- Missing direct include (works through transitive includes on libstdc++, MSVC STL and today's libc++; would
  break under libc++ with `_LIBCPP_REMOVE_TRANSITIVE_INCLUDES`): `app/tests/unit/TestSupport.h:22` uses
  `std::runtime_error` without `<stdexcept>`.
- No shell flag is needed yet. Later golden views (selected part, explode, x-ray, other objects) need
  `fulmetry --render` options for camera/selection/explode in `app/shell/src/main.cpp` (integrator).

## Decisions and findings

- Tolerances for `rover-fake-iso`: THRESHOLD 8, MAX_RMSE 6.0, MAX_FRACTION 0.002 (128 of 64000 pixels).
  The fake renderer only produces exact palette colours (shade is 0.6 or 1.0), so cross-compiler drift can only
  flip whole edge pixels. Measured locally: GCC 13 `-O2`, GCC `-O3 -ffp-contract=fast -march=haswell` (FMA),
  GCC `-O2 -ffast-math`, clang 18 `-O0` and clang `-O2 -ffp-contract=fast -march=haswell` all render bit-identical
  to the golden (RMSE 0). The limits still allow ~50 flipped high-contrast edge pixels for arm64/MSVC.
- Moving the camera head 10 mm (`golden_rover-fake-iso-head-moved`, generated from the fixture at configure time
  with `string(JSON)`) gives RMSE 14.1 and 0.76 % over threshold: 2.3x and 3.8x the limits.
- No build-dir cache in CI: the fakes-only build is ~12 Ninja steps (seconds), and a restored Ninja dir is rebuilt
  anyway because checkout resets source timestamps. Revisit with ccache once Wicked/OCCT build in CI.
- macOS runner is `macos-latest` (Apple silicon); `macos-14` jobs were cancelled before start.
- `enable_testing()` now runs before the module `add_subdirectory` calls, so module-level `add_test()` registers.
- `ci` test preset: `--output-on-failure`, `noTestsAction: error`, 300 s per-test timeout.
- `.gitignore` is now owned by S10 (`tools/streams.json`); `.fulmetry/` (per-project build outputs) is ignored.
