# S6 Sheets

**Status:** wave 1 done on `s6/kicad-parser` (KiCad 8 parser, nets, rover fixture), waiting for review.

## Current task (wave 1)

Write a KiCad 8 .kicad_sch parser (S-expressions) for symbols, pins, wires, labels and nets, plus a small rover main-board schematic fixture.

**Check:** Unit tests parse the fixture and find the expected refs, pins and nets (e.g. VBAT reaches U1 and the motor driver).

## What landed

- `fulmetry_sheets` is now a STATIC library (always built, standard library only).
- `fulmetry/sheets/SExpr.h`: S-expression reader. Iterative, depth limit 256, size limit 64 MiB,
  locale-independent numbers. Malformed input returns `Error{"parse_error"}`, never crashes.
- `fulmetry/sheets/Schematic.h`: `Result<Schematic> parseSchematic(std::string_view)` and
  `loadSchematic(path)`. Extracts lib_symbols (pins with number, name, electrical type, position,
  unit, body style, hidden), placed symbols (reference, value, footprint, lib_id, position,
  rotation, mirror, unit), wires (polylines split into segments), junctions, local, global and
  hierarchical labels, power symbols and no-connects. Bad structure returns `invalid_schematic`.
  `placedPins()` applies the symbol transform.
- `fulmetry/sheets/Netlist.h`: `std::vector<Net> buildNets(const Schematic&)` and `Netlist` with
  `netOf(ref, pin)` (pin number or name) and `find(name)`.
- `fixtures/rover/kicad/rover-main.kicad_sch`: rover main board, self-contained lib_symbols.
  U1 ESP32-WROOM-32E (pin subset), U2 DRV8833 + J3/J4 motor connectors, U3 AP2112K-3.3 with C3/C4,
  J1 1S battery (VBAT, GND), R1 + D1 status LED on IO2, J2 servo header (SERVO_PWM, VBAT, GND),
  C1/C2 for the DRV8833 VINT and VCP pins, PWR_FLAGs on VBAT and GND.

## Decisions and findings

- Namespace `fulmetry::sheets`; no change to `app/core`. The `Anchor.sheetRef/sheetPin/sheetNet`
  strings map directly onto `Netlist::netOf(ref, pin)` and `Netlist::find(net)`.
- Transform: library frame is y-up, sheet is y-down; rotation is counter-clockwise on screen;
  mirror is applied after rotation (`mirror x` flips y, `mirror y` flips x), as in KiCad.
- Connectivity: points match on a 0.1 um grid. A pin, label, junction or wire end on a wire's
  interior joins that wire; plain crossings do not. Same-name labels and power symbols merge.
  Only power symbols with a `power_in` pin name a net, so PWR_FLAG never does.
- Net names follow KiCad: power > global > hierarchical > local label; otherwise
  `Net-(U1-IO2)` (prefer named pins, then alphabetical), `Net-(R1-Pad1)`, and
  `unconnected-(U1-RXD0-Pad34)` for lone pins. Local label nets are plain (`AIN1`), where KiCad's
  netlist writes `/AIN1`.
- Not handled yet: hierarchical sheets, buses, implicit hidden `power_in` pins on non-power parts.
- The fixture is generated by a short script and checked by hand; numbers are on the 1.27 mm grid.

## KiCad verification

- Ubuntu 24.04 only ships KiCad 7.0.11 (`apt install kicad`, about 200 MB); adding the KiCad 8 PPA was
  not allowed in the agent sandbox. KiCad 7 cannot open KiCad 8 files and its `kicad-cli` has no ERC.
- What was verified: a copy down-converted to the KiCad 7 format (version 20230121, `(hide yes)` to
  `hide`, no `generator_version`/`exclude_from_sim`) opens in `kicad-cli 7.0.11`, and its
  `sch export netlist` gives exactly the nets `sheets_tests` expects (21 nets, same nodes, same
  auto names apart from the `/` prefix).
- Not verified: opening the KiCad 8 file itself in KiCad 8, and ERC. To do on a machine with KiCad 8:
  `kicad-cli sch erc fixtures/rover/kicad/rover-main.kicad_sch`.
