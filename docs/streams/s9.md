## Decisions and findings

- **SDK:** `@modelcontextprotocol/sdk` 1.32.2, low-level `Server` (not `McpServer`), because tool schemas come
  straight from the contracts as JSON Schema and `McpServer.registerTool` wants Zod. Stdio transport in the CLI,
  in-memory transport in tests.
- **Tools:** name = method with `.` as `_`; inputSchema = contract `params` verbatim; description names the method,
  toolkit and `since` milestone. Toolkit = method prefix before the first dot. `--toolkits a,b` (or
  `FULMETRY_TOOLKITS`) serves a subset; an unknown toolkit name is a startup error, a call to a disabled tool is
  an `isError` result.
- **Params are validated by the worker only.** The server forwards arguments as they are, and the worker's
  `-32602 params do not match the contract` (with per-path errors in `data`) becomes the `isError` text. One
  validator, the same one the app gets.
- **WorkerClient:** one worker process, requests multiplexed by numeric id, per-request timeout
  (`FULMETRY_WORKER_TIMEOUT_MS`, default 120 s). On timeout the worker is killed and replaced, because it answers
  strictly in order and a stuck call would block every later one. A dead worker fails its pending calls
  (`-32011`) and is restarted with backoff (100 ms doubling to 5 s, reset after 10 s up); a call while it is down
  starts it at once. Calls are never retried automatically, since a tool like `cad.build` may have side effects.
- Default worker cwd is `<repo>/worker`, so `python3 -m fulmetry_worker.server` imports the package even when
  it is not pip-installed (it still needs `jsonschema`).

## Proposed contract changes (for a `contract/` PR, not made here)

1. **`description` on each method contract**, and `description` on each params property. Today the tool
   descriptions are generated from the method name and milestone, which tells an agent little about what
   `part` or `projectRoot` should hold (an id like `part:rover/wheel-l`? a path relative to what?).
2. **Report implemented methods.** Add `methods: {"cad.build": "implemented" | "not-implemented"}` (or a list)
   to the `worker.ping` result, so toolkits can hide or mark tools whose milestone has not landed instead of
   letting an agent find out by calling them.
3. **`timeoutMs` hint per method contract.** `worker.ping` should fail in seconds; `cad.build` and `print.slice`
   may legitimately take minutes. The client now uses one timeout for all.
4. **`idempotent` / `readOnly` flag per method**, mapped to MCP tool annotations (`readOnlyHint`,
   `idempotentHint`) and used to decide whether a call may be retried after a worker crash.
5. **Expose `result` as MCP `outputSchema`** with `structuredContent` once the result schemas are final; held
   back for now because a client validates structuredContent against outputSchema, and a contract fix would then
   break agents mid-session.
