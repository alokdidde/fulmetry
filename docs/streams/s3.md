# S3 CAD kernel

**Status:** wave 1 done on `s3/occt-kernel`. `OcctCadKernel` passes `CadKernelConformance` on the rover fixture.

## Current task (wave 1)

Implement OcctCadKernel (ICadKernel on OCCT): STEP loading, tessellation with a triangle-to-face map, bounding box, mass, min distance, horizontal sections.

**Check:** OcctCadKernel passes CadKernelConformance on STEP boxes generated from the rover fixture.

## OCCT

- Built against **OCCT 7.6.3** (Ubuntu 24.04 packages). `app/cad/CMakeLists.txt` requires 7.6 or newer.
- Found with `find_package(OpenCASCADE CONFIG)` (no version argument: OCCT's config-version file only accepts
  exact matches). Links only TKernel, TKMath, TKG2d, TKG3d, TKGeomBase, TKBRep, TKGeomAlgo, TKTopAlgo, TKPrim,
  TKBO, TKShHealing, TKMesh, TKXSBase, TKSTEP, TKSTEPBase, TKSTEPAttr, TKSTEP209 (no visualization, no OCAF).
- Install on Ubuntu 24.04:

  ```sh
  sudo apt-get install -y libocct-foundation-dev libocct-modeling-data-dev libocct-modeling-algorithms-dev \
                          libocct-data-exchange-dev libtbb-dev
  ```

  `libtbb-dev` is needed because Debian's OCCT CMake targets name `/usr/lib/x86_64-linux-gnu/libtbb.so`.
  `libocct-data-exchange-dev` pulls in the OCAF and visualization dev packages; the kernel does not link them.
- vcpkg (`full` preset): port `opencascade`, which exports the same TK* targets.

Build and test:

```sh
cmake -S . -B build/occt -G Ninja -DFULMETRY_WITH_OCCT=ON -DCMAKE_COMPILE_WARNING_AS_ERROR=ON
cmake --build build/occt && ctest --test-dir build/occt --output-on-failure
```

With `FULMETRY_WITH_OCCT` OFF (default, `ci` preset) `fulmetry_cad` stays an INTERFACE library and nothing
OCCT-related is configured.

## Decisions and findings

- **Public header has no OCCT types** (`app/cad/include/fulmetry/cad/OcctCadKernel.h`, pimpl). With OCCT ON,
  `fulmetry_cad` is a STATIC library and defines `FULMETRY_HAS_OCCT=1` publicly so the shell can choose it
  over the fake.
- **Frames.** `tessellate`, `boundingBox`, `massProperties` and `section` answer in the part's local frame (the
  STEP file's frame, or `Part.bounds`), same as the fake. `minDistance` places both shapes with the full
  `Part.placement` (position and rotation, quaternion w,x,y,z).
- **loadPart.** Empty path: `BRepPrimAPI_MakeBox` from `Part.bounds` (error `invalid_bounds` if any side is 0).
  Otherwise `STEPControl_Reader` (OCCT converts to mm). The path is used as given; resolving `Part.stepFile`
  against the project root is the caller's job. Errors: `io_error`, `invalid_step`, `occt_error`
  (any `Standard_Failure` is caught; nothing throws across the interface).
- **Face ids** are `"<part id>#<n>"`, n from 0 in `TopExp::MapShapes(shape, TopAbs_FACE)` order (the fake uses
  the same form). Stable across tessellation tolerances because they depend only on topology.
- **Tessellation.** Each call clears the old triangulation (`BRepTools::Clean`) and meshes with
  `BRepMesh_IncrementalMesh(linear tolerance, angular 0.5 rad)`. Vertices are per face (not shared), normals
  come from the surface at each UV node, winding and normals follow face orientation (outward on solids).
- **Bounding box** is `BRepBndLib::AddOptimal` without triangulation or tolerance enlargement, so it is tight.
- **minDistance** is `BRepExtrema_DistShapeShape`; if the result is positive but one part is fully inside the
  other (vertex classified IN a solid), it returns 0.
- **Section** works on any plane, not only horizontal ones. `BRepAlgoAPI_Section` edges are chained with
  `ShapeAnalysis_FreeBounds::ConnectEdgesToWires` and discretized with `GCPnts_TangentialDeflection`
  (0.1 rad, 0.01 mm). Closed loops repeat their first point at the end, like the fake.
- Extra: `OcctCadKernel::writeStep(part, path)` writes a loaded shape to STEP (used by the round-trip test).

## Checks added

- `cad_tests` (ctest, `app/cad/tests`, built only with `FULMETRY_WITH_OCCT=ON`):
  - `CadKernelConformance` with an `OcctCadKernel` factory on the rover fixture.
  - Box written to STEP, loaded back: volume, mass, centroid and bounds match.
  - Tessellation of a box: 6 faces with ids `#0..#5`, stable across tolerances, unit outward normals, winding
    agrees with normals, total area exact.
  - `minDistance`: separated (with placement), touching, contained, diagonal gap, unknown part.
  - `section`: horizontal cut is one closed loop with the right perimeter, cut above the part is empty,
    vertical cut works.
  - `loadPart` errors: missing STEP file, empty bounds, unknown part.
